# 设计文档：项目建档交接工作流（PROJECT_HANDOFF）

- 日期：2026-09-05
- 状态：待评审
- 所属应用：TraeCheckin（Trae 每日签到助手，WinForms / .NET 9）

## 1. 背景与问题

用户在 TraeWork（TRAE SOLO CN 桌面客户端）上使用多个账号。切换账号后，新账号的任务
列表是空的，旧账号的任务/对话历史无法直接带过去。用户最初希望"把 A 号全部对话搬到 B
号任务列表"，并期望程序自动完成（一个任务常有上百条消息，逐条复制不可接受）。

### 1.1 探测结论（2026-09-05 实测）

为评估"程序化搬对话"的可行性，做了只读探测，结论如下：

| 读侧通道 | 结果 |
|---|---|
| 界面全选复制 | ✗ 对话区文字"看得到但拷不了"（用户实测，产品禁用选择） |
| 本地 SQLite 直读 | ✗ `ModularData\ai-agent\database.db` 头部高熵乱码，整库加密（`-wal/-shm` 为同名伪装） |
| Chromium 调试口（CDP） | ✗ 主进程启动参数无 `--remote-debugging-port`；仅 2 个内部端口（17788 非 CDP、51000 自定义协议） |
| Windows 无障碍（UIA） | ✗ 所有窗口仅暴露 13 个节点、0 个 Text/Value 模式（内容不进入无障碍树） |
| 服务端私有接口 + 系统加密令牌 | ✗ token 在系统凭据加密区，抓取属灰区且有风控风险，不做 |

**结论：TraeWork 对对话内容做了刻意设防（禁选 + 加密 + 无调试通道），不存在干净的程
序化读对话通道，因此"逐条搬对话到 B 号"不可行，也不应通过绕过手段实现。**

### 1.2 需求重定位

澄清后，用户的核心诉求实际是：

1. **保住项目成果**——项目文件/代码本来就在本地工作区，随文件夹走，换号不丢；
2. **让 B 号能接手项目**——B 号打开项目后能快速了解背景、进度、踩坑与下一步。

丢失的只有"对话里未落盘的过程知识与结论"。因此采用**建档交接**：把每个项目的交接知识落
成仓库内普通文档 `PROJECT_HANDOFF.md`，随 git/文件夹迁移，任何账号打开项目先读它即可
接手。不触碰 TraeWork 对话锁。

## 2. 目标与非目标

### 2.1 目标
- 在 TraeCheckin 内新增「项目交接」页面（侧边栏第 5 项）。
- 选择父目录 → 枚举其下含 `.git` 的子目录为候选项目 → 批量生成各项目根的 `PROJECT_HANDOFF.md`。
- 自动生成第 1–5 节（README / git log / 目录结构）；第 6、7 节由用户在**内置编辑区**手写并保存。
- 重复生成时**保留已手写的第 6/7 节**，只刷新自动节。
- 页面内可查看/编辑/保存每一份档案；日志区输出逐项结果。

### 2.2 非目标
- 不读取、迁移、导出 TraeWork 对话（存在刻意设防，不做绕过）。
- 不做 OCR / 截图留档（如需另行评估）。
- 不修改 TraeCheckin 既有签到、云端部署逻辑。

## 3. 产物格式：PROJECT_HANDOFF.md 模板

文件放在**项目仓库根目录**，UTF-8。首部用注释标记"程序托管区 / 用户手写区"边界，便于程序
解析保留手写区。

```
# 项目交接档 <项目名>

> 由 TraeCheckin 建档交接生成：YYYY-MM-DD HH:mm · 最近提交 <短哈希> <主题>
> 打开本项目时请先读本文件。

## 1. 一句话定位
<自动：README 首段/首行，截取 1–2 句；无 README 则为"（未检测到 README）">

## 2. 快速开始
<自动：README 中构建/运行相关命令片段；无则留占位>

## 3. 关键路径
<自动：README、docs、主要源码目录、解决方案/项目文件的相对路径清单>

## 4. 最近进展
<自动：git log -20 --oneline，按时间倒序；非 git 目录不出现本节>

## 5. 进行中事项
<自动：README 里的 TODO 章节 / 最近提交中的 WIP 关键字提示，供人确认>

<!-- ===== 以下为人工手写区，重新生成时程序不会覆盖 ===== -->

## 6. 已知坑与约定
（待补充）

## 7. 下一步建议
（待补充）
```

> 命名约定：生成的文件必须叫 `PROJECT_HANDOFF.md`，放在项目根。

## 4. 项目识别与枚举

- 输入：一个父目录（`FolderBrowserDialog` 选择）。
- 枚举：父目录的直接子目录中，**含 `.git` 目录**者判定为候选项目（门槛=仅 `.git`）。
- 无 `.git` 的子目录不列出（不采用 README/代码启发式）。
- 父目录自身若含 `.git` 且被选中目录包含它，不额外处理（只处理直接子目录，避免递归）。
- 排序：按目录名升序，展示为勾选列表，默认全选。

## 5. 生成与更新语义（幂等）

- 生成器每次对选定项目执行"重建自动区，保留手写区"：
  1. 读取现有 `PROJECT_HANDOFF.md`（若存在），抽取 `## 6.` 与 `## 7.` 之间的内容（含小节标题），作为"手写区"缓存；
  2. 重新采集自动数据，重写整份文件；
  3. 若缓存到的手写区非空（含用户实际内容），回填到新文件的第 6/7 节；若原文件第 6/7 节仅为占位符文本 `（待补充）`，视为空，不保留占位符。
- 采集失败的项目不中断批次：逐项独立 try/catch，日志输出"成功/失败原因"，失败项不落盘。

### 5.1 自动节数据源
- **1 一句话定位 / 2 快速开始**：README 优先取 `README.md`，不存在则取 `README.en-US.md`，都不存在则为空节占位。对 README 仅做启发式截取：
  - 定位：取非空首段前 2 句（按句号/换行切分，最长 200 字符）。
  - 快速开始：匹配常见命令行（`dotnet run|build`、`python …`、`npm …`、`/xxx` 插件命令等）所在行附近，最多收集 6 行；无匹配则占位。
- **3 关键路径**：相对项目根列出 README、docs（若存在）、`*.sln`/`*.csproj`/`package.json`/`*.py` 入口脚本（最多列 10 个文件/目录，用列表形式）。
- **4 最近进展**：`git log --oneline -20`（UTF-8 输出），过滤空；失败（非 git / 无提交）则该节占位。
- **5 进行中事项**：README 中含 `TODO`/`待办`/`进行中`/`下一步` 的行（最多 10 行）；以及 git 最近 20 条中提交信息含 `WIP`/`in progress` 的条目提示；均无则占位。

### 5.2 手写区 UI（内置编辑区）
- 列表选中某项目后，下方编辑区显示当前项目档案的"手写区草稿"（仅第 6/7 节标题与内容）；
- 「保存手写内容」把草稿写入该项目的 `PROJECT_HANDOFF.md`（若文件尚未生成则先按当前自动数据生成再写入）；
- 保存成功即日志提示，并可选"打开所在文件夹"。

## 6. 技术方案（TraeCheckin 内集成）

### 6.1 文件变更
| 文件 | 变更 |
|---|---|
| `Forms/MainForm.cs` | 侧边栏加第 5 项「项目交接」（`NavItem("项目交接", 4)`），导航面板 `Height 200→244`；`BuildContentHost()` 追加 `_pages.Add(BuildHandoff())` |
| `Forms/MainForm.Handoff.cs`（新增 partial） | `BuildHandoff()`：页面布局与全部事件（选目录/列表/生成/编辑/保存），沿用 `MainForm` 配色常量与 `SetLog` |
| `Services/HandoffGenerator.cs`（新增） | 纯逻辑、无 UI 依赖：枚举项目、采集自动节、读写/解析档案（保留手写区）、git log 读取（调 `git.exe`，通过 `Process`，设 UTF-8，超时 10s） |
| `Services/HandoffGenerator.cs` 内附 DTO | `ProjectInfo` / `HandoffSections` 等小 DTO 一并放入生成器文件，不另立文件 |

- 生成器保持与 `MainForm` 解耦，便于后续对该类补单元测试（Tests 工程在仓库外，CI 不跑，仅本地）。
- git 命令不引第三方库：直接 `git -C <repo> log --oneline -20`。找不到 git 或无 `.git` 时相应节置占位而不抛错。

## 7. 边界情况处理
- 目录无 `.git` 的任何子项目：不列出（当前版本不加启发式识别）。
- 父目录下没有任何项目：日志提示，不报错。
- `README.md` 缺失：节 1/2/5 显示占位文本，档案照常生成。
- 档案内容含大段用户手写：解析手写区以 `## 6.`…下一个 `## ` 或文件尾为界，避免误吞自动节。
- 生成期间文件被占用：单项目失败，不影响其余项目。
- git log 中文/UTF-8：`ProcessStartInfo.StandardOutputEncoding = UTF8`。

## 8. 验收标准
1. 打开「项目交接」页，选含多个 git 仓库的父目录，能列出并默认全选。
2. 点生成：各项目根出现 `PROJECT_HANDOFF.md`，第 1–5 节有据可查（README 有内容时非空），第 6/7 节为占位。
3. 在编辑区写入第 6/7 节并保存；再次点生成后手写内容仍在（不覆盖）。
4. 已有档案但第 6/7 节仍是占位符的项目：重新生成后不残留占位符。
5. 无 README 的仓库也能生成（带占位节），不崩溃。
6. 单个坏项目（如只读目录）不影响批次其余项目完成。
7. 主界面其余 4 页功能不受影响（回归冒烟：本地签到、云端部署查看正常）。

## 9. 不做（明确排除）
- 对话迁移 / 对话读取（含截图 OCR、UI 自动化、加密库解密、内部接口逆向）。
- 上传交接档到任何远程服务；仅本地文件。
- 修改 TraeCheckin 云端/签到相关逻辑。
